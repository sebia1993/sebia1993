HOW I TROUBLESHOOT NETWORKS

장애는 제품명이 아니라 패킷이 지나가는 순서로 좁힙니다.

아래 단계는 “정상/비정상”을 빨리 단정하기 위한 체크리스트가 아니라, 다음 확인 지점을 결정하기 위한 흐름입니다.

01 Endpoint / IP Configuration

링크 상태, IP 할당, Gateway/DNS 설정, 동시에 활성화된 유선·무선·VPN 경로를 먼저 구분합니다.

02 Wireless Association / RF

Association, RSSI/SNR, Channel, DFS, PHY, BSSID 변화와 로밍 상태를 확인합니다.

03 Authentication / AAA

802.1X/EAP, RADIUS Request/Response, ClearPass 결과와 인증 실패 지점을 확인합니다.

04 Authorization / Segmentation

Role, VLAN, ACL과 정책 적용 결과가 의도한 사용자 세그먼트와 일치하는지 확인합니다.

05 L2 Switching

MAC 학습, VLAN/Trunk, LACP/STP 상태를 통해 프레임이 다음 Hop까지 전달되는지 확인합니다.

06 L3 Routing

ARP/Neighbor, Gateway, Routing Table, Longest Prefix Match, Next Hop과 동적 라우팅 상태를 확인합니다.

07 Security / Middlebox

ACL, Stateful Session, NAT, Firewall/Proxy 정책처럼 경로 중간에서 패킷 상태를 바꾸는 요소를 확인합니다.

08 Transport / Application

DNS, TCP Handshake/RST, TLS/HTTP 결과를 확인하고 네트워크 문제와 서비스 문제의 경계를 좁힙니다.

ENGINEERING PRINCIPLES

운영 자동화에서 중요하게 보는 것

01

Observe before changing

먼저 읽기 전용 관측으로 상태를 확보하고, 상태 변경 기능은 별도의 승인과 안전 경계로 분리합니다.

02

Unknown is not healthy

수집 실패나 불완전한 입력을 “정상”으로 추정하지 않고 확인 불가 상태로 분리합니다.

03

Evidence over labels

장애 원인을 바로 단정하지 않고 어떤 패킷·세션·상태가 관찰되었는지와 판단 한계를 함께 기록합니다.

04

Reproducible validation

실장비 증거와 합성 테스트를 구분하고, 공개 가능한 Fixture와 CI로 재현 가능한 검증 경로를 남깁니다.
